# Photo exploration and image performance

Requested behavior: explore clipped parts of a photo by moving within its existing box, without a popup or layout change. Shared object-cover Photo images now map mouse coordinates to the full object-position range. This applies to safari cards, photo strips and gallery photos. It explores the source progressively; it does not show the entire source simultaneously inside a differently shaped box. Non-cropped/logo images and the existing decorative crossfade backgrounds are excluded.

One queued animation frame per image writes the latest coordinates, with a 140ms CSS object-position transition for gentle movement. It is not a claim that every rendered animation frame instantly matches the pointer. Pending work cancels and the original CSS crop (including the hyena’s 15% focal point) returns on leave, cancellation, blur or unmount. Pointer panning requires a mouse, fine hover and no reduced-motion preference; touch scrolling is left alone. Focusable photos expose arrow-key controls and Escape reset with an inset outline. Keyboard exploration remains immediate under reduced motion. The earlier decorative card zoom is suppressed during inspection so object-cover reaches both crop edges within the unchanged clipping frame.

Performance: all 12 original source hashes match the existing pinned manifest; all 72 derivative dimensions/byte sizes were checked. The same source photos were encoded at AVIF quality 55 and WebP quality 80 (previously 75/90). Total derivative bytes decreased from 18,104,353 to 11,003,559 (39.2%); AVIF decreased 44.8%, WebP 35.4%. This is a file-size measurement, not a measured production page-load improvement. The generator stages files and rejects changed source hashes before publishing generated assets.

Lazy images use the standard single sizes attribute list: `auto, [existing fallback]`. Auto is emitted only with loading=lazy, with explicit viewport-based fallback values for older browsers. Safari card fallbacks now reflect their grid columns. Heroes remain eager and high priority; below-fold photos remain lazy. Responsive AVIF/WebP, intrinsic dimensions and async decoding are retained. Public /images/* has a one-hour browser cache header; these stable filenames are not declared immutable. Authenticated/HTML response caching remains unchanged.

Proof: all 150 tests across 29 files passed, TypeScript/build passed, lint has no errors and the same 12 existing warnings. Focused tests cover bounds, latest-event coalescing, leave/unmount cleanup, touch/reduced motion, keyboard/reset and auto-size emission. Browser checks showed the rhino upper crop at ~6% and lower crop at ~96%, with the same currentSrc, no zoom and no gap around the rounded frame. Leave restored 50%/50%; arrow keys moved the view; reduced motion disabled pointer movement/transitions. Public pages were checked at 320, 768 and 1280px without horizontal overflow. Screenshots were saved for upper/lower crops.

DeepSeek reviewed the non-sensitive feature summary. Its CSS interpolation concern does not apply: the transitioned property is object-position, not the custom property; smoothing is intentional. Its clipping concern was checked visually in the rounded rhino frame. Its sizes concern was checked against the emitted single comma-separated sizes list and lazy-only branch; there are no duplicate sizes attributes. No unsupported speculative changes were adopted.
